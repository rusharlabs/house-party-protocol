01

Onde os mapas estão na 2.11

Todo mapa do HPP é uma projeção de arquivos que você já tem — manifestos, event logs, JSON que você fornece — e a mesma entrada imprime a mesma saída.

comandoformatos
hpp graph --view capability|operational|agent|evidence|codeJSON ou Mermaid
hpp map lane|agent|monitor|contextJSON ou Mermaid
hpp work plan|wavesJSON ou Mermaid
hpp doctor --matrixMarkdown: host × módulo × canal

A view code mostra quais superfícies cada módulo declara; ela não é um grafo do seu código. O Lane Dashboard do lane-kit, desde a 2.10.0, é uma página no endereço de loopback que você liga e desliga, mostrando o lane board, as lanes vivas, a caixa de mensagens de cada lane e o backlog com as suas waves; toda ação que ele oferece também é um comando de terminal.

02

2.12: ver o estado

Mermaid para os mapas e para o WorkGraph, o primeiro item planejado para esta etapa, saiu na 2.11.0 (a tabela acima). A versão 2.12.0 acrescenta as visões abaixo.

  1. Um mapa de feed. Uma linha do tempo de claims, vereditos, mensagens enviadas e arquivadas, entregas e handoffs, com o último heartbeat de cada lane. A linha do tempo informa a precisão dos horários nos registros que o harness já escreve.
  2. Um atlas HTML estático. hpp atlas --html --target . reúne as projeções do CLI do projeto em um arquivo autocontido. Cada visão mostra seu comando e o hash da projeção, e indica entradas opcionais que não foram fornecidas. O atlas abre como arquivo e roda sem servidor.
  3. As visões no Lane Dashboard. O dashboard usa as mesmas projeções para o feed e os resumos de capacidades, ciclo operacional, evidência e papéis dos agentes. As visões que exigem arquivos adicionais ficam no atlas offline.

03

2.13: inspecionar o projeto antes do trabalho paralelo

hpp inventory começa pelo universo versionado e pelas lacunas explícitas. hpp codegraph build acrescenta relações AST Python conservadoras e imports lexicais JavaScript/TypeScript, com cobertura e referências não resolvidas. Um indexador declarado usa hpp.codegraph/v1 e continua opcional. Construa em stdout ou grave explicitamente o cache por commit, com entradas stale indicadas.

Medições fresh alimentam hpp lanes propose, avisos de acoplamento no WorkGraph e nos mapas de lanes, impacto opcional na atestação, visões do atlas e o próximo comando sugerido pelo status. Propostas exigem aprovação antes de aplicar territórios. Consulte o guia de inventário do projeto para comandos, privacidade e limites do indexador externo.

Depois da 2.13

05

O que o projeto não vai fazer

Estas recusas são as do MANIFESTO.pt-BR.md, "O que o projeto se recusa a fazer". Elas são decisões, não lacunas, e nada neste roadmap as muda. O manifesto traz o motivo de cada uma e as exceções delimitadas para módulos; onde este resumo e o manifesto divergirem, vale o manifesto.

  • Sem daemon, sem servidor, sem scheduler. Uma checagem que não rodou não foi rodada. O atlas descrito acima abre como arquivo por esse motivo.
  • Sem chamada de modelo. O harness roteia o trabalho para um tier e um id de provedor que você declarou, e não guarda credencial.
  • Sem banco de grafos. Todo mapa é uma projeção de arquivos que você fornece; o grafo de código introduzido na 2.13 é construído sob demanda, indexado pelo hash do commit e reportado como stale quando está velho.
  • Sem escrita silenciosa. Os instaladores planejam primeiro e só escrevem num segundo passo explícito; o wiring de settings e hooks é impresso para uma pessoa colar.
  • Nenhuma promessa aceita como evidência. O done gate roda de novo os comandos do critério; uma tag de conclusão numa transcrição não para nada.
  • Sem paridade de host por afirmação. A cobertura é declarada por módulo como native, explicit-command ou unsupported.
  • Sem números de manchete. Um número aparece ao lado do comando que o produziu, ou não aparece.
  • Sem telemetria remota. Nada sai da máquina a menos que uma pessoa rode um comando que o envie.

06

Como participar

Responda na discussão do roadmap com o seu setup — host, bundle e o comando que você rodaria — um ponto por comentário; um voto positivo num comentário conta como concordância. Uma proposta que precisa de desenho próprio vai para a categoria Ideas, como o SUPPORT.pt-BR.md descreve. Esta página muda por pull request, e a mudança fica registrada no CHANGELOG.
