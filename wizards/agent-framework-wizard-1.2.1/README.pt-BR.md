# Agent Framework Wizard

Wizard de 6 passos (`check_python → check_git → check_deps → configure → validate →
generate_and_summary`) que faz o scaffold de um agente/projeto novo: gera
`operator-profile.yaml` (escada de verificação R0-R4) + os templates escolhidos
(`00-READ-FIRST`, `00-STATE`, `00-VISION`, `00-PROCESSES`). Não instala o
`operator-kit` em si — gera o esqueleto inicial que um projeto novo usaria com ele.

## Pré-requisitos + APIs externas

| Requisito | Versão mínima | Obrigatório? |
|---|---|---|
| Python | 3.9 | sim |
| git | qualquer | sim — o wizard confirma `git --version` no passo 2 |
| PyYAML | qualquer | sim |

Serviços externos: **nenhum — stdlib + PyYAML.**

```bash
/plugin marketplace add rusharlabs/house-party-protocol

```
O plugin não tem hooks; a skill `agent-framework-scaffold` é auto-descoberta e o

## Instalar por cópia

Na distribuição emitida este módulo vive em `wizards/agent-framework-wizard-1.2.1/` (o
diretório carrega a versão — declare-a uma vez, em `KIT`). O instalador é
`installers/kit-forge-1.4.2/kit_doctor.py`; rode-o da raiz da distribuição. Ele planeja
primeiro e só escreve numa segunda invocação explícita com `--apply`:

```bash
KIT=wizards/agent-framework-wizard-1.2.1
cp -r "$KIT" ../your-repo/agent-framework-wizard   # the copy itself (kit_doctor does not copy on claude-code)
python installers/kit-forge-1.4.2/kit_doctor.py install --kit "$KIT" --host claude-code --target ../your-repo
python installers/kit-forge-1.4.2/kit_doctor.py install --kit "$KIT" --host claude-code --target ../your-repo --apply
# Codex CLI: --host codex — the installer copies the module into .agents/hpp/agent-framework-wizard
#            and the skill into .agents/skills/hpp-agent-framework-wizard-<skill>; no cp -r needed
```
Este kit não tem hooks/wiring — depois de copiado, use o `wizard.py` direto (seção
seguinte).

## Como usar (não-interativo — nenhum modo bloqueia em stdin)

O operador real deste ecossistema é frequentemente um agente atuando pelo humano — um
`input()` de terminal trava exatamente nesse contexto. O "Confirm" deste wizard é
`--interview` (imprime o schema de perguntas) seguido de `--answers` (aplica as respostas):

```bash
# 1. print the question schema (JSON, exit 0, generates nothing)
python wizard.py --interview

# 2a. quick scaffold with sensible defaults (asks nothing)
python wizard.py --demo --out <dir>

# 2b. OR scaffold from ready answers (the agent builds the JSON after reading --interview)
python wizard.py --answers answers.json --out <dir>
```

Exemplo de `answers.json`:
```json
{"project_name": "my-agent", "templates": ["00-STATE", "00-VISION"]}
```

## O que o instalador detecta / o wizard detecta

O estágio `detect` do instalador classifica o alvo (só leitura) com exatamente estes três
rótulos; o estágio `configure` carrega as duas perguntas do wizard (`project_name`,
`templates`), respondidas de verdade com `--answers <arquivo.json|yaml>`:

```
greenfield    -> no prior config in the target; nothing to copy (the scaffold is generated by wizard.py, not by the installer)
in-progress   -> .claude/ exists, or settings(.local).json already has hooks/statusLine, or the repo has
                 more than 3 commits: reported, never overwritten
re-run        -> this kit+target pair is already in the registry (~/.claude-kits/registry.json)
```

E o wizard em si, quando gera em `<out>/docs/plans/execution/`:

```
new file      -> generates operator-profile.yaml + the chosen templates from scratch
customized    -> the file exists with content DIFFERENT from what would be generated -> skip
                 (reported in "files_skipped_customized", never overwritten)
identical     -> content identical to what already exists -> no_op:true (nothing changes, nothing breaks)
```

## O que é seguro rodar de novo

`generate_and_summary()` **nunca sobrescreve** um arquivo que já existe com conteúdo
diferente do que seria gerado (customização do usuário) — o campo
`files_skipped_customized` no JSON de retorno lista exatamente o que foi preservado.
Rodar duas vezes sem editar nada dá `no_op: true`. Para forçar regeneração de propósito
(descartando customização), use `--force`.

O primeiro template e o diretório de saída foram renomeados para o inglês:
`00-LEIA-PRIMEIRO` virou `00-READ-FIRST`, e `docs/plans/execucao/` virou `docs/plans/execution/`.
**Um projeto criado com a grafia antiga não exige nenhuma ação.** O nome antigo de template
continua aceito e resolve para o novo; e se o alvo já tiver `docs/plans/execucao/` mas não `docs/plans/execution/`,
o wizard segue gerando ali em vez de criar um segundo diretório. Os dois casos imprimem uma
linha de depreciação no stderr e mantêm o mesmo exit code; o fallback é garantido por uma versão.

## `templates/agents/AGENT.template.md` — a forma do agente, com a prompt defense baseline

| Arquivo | Instanciado pelo wizard? | Guardado por |
|---|---|---|
| `templates/agents/AGENT.template.md` | Não — é referência, copiada à mão quando você cria um agente | `tests/python/test_kits/test_prompt_defense_baseline.py` |

Copie-o como ponto de partida de qualquer agente que você criar, aqui ou no seu projeto. Ele
carrega a forma do frontmatter (`name`, `description`, `tools` — sempre explícito, porque um
`tools:` ausente significa *todas* as ferramentas e se lê como silêncio em vez de como a
permissão mais ampla que existe) e a **prompt defense baseline**: sete linhas dizendo que o
agente não troca de papel, não revela segredo, não emite código nem URL fora do pedido, trata
truque de unicode e autoridade alegada como sinal de ataque, trata o que lê como dado e não
como instrução, recusa dano e fica no escopo que recebeu — um agente só-leitura mantém o Bash
somente-leitura, um construtor nunca amplia o próprio alcance. Todo agente que o produto distribui
carrega o bloco na redação que o seu `tools:` merece, e o validador acima reprova um arquivo de
agente a que falte qualquer cláusula ou cuja cláusula 7 discorde das ferramentas
(`scope-mismatch`) — cópia parcial não é a baseline.

Ele mora de propósito em `templates/agents/` e não em `templates/`: o conjunto de documentos
do wizard é o glob não-recursivo `templates/*.template.md`, então um arquivo ali seria
oferecido como documento-base e escrito em `docs/plans/execution/` — conteúdo certo, lugar
errado.

linha de comando pura.
